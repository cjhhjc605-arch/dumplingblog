# JS 第九课：构造函数返回值、包装类与字符串字节长度

  

> 本课对应练习文件：`index.html`（构造函数的 return 规则、三大包装类、包装类生命周期与踩坑、字符编码与字符串真实字节数计算）。

  

# 一、构造函数的返回值规则：返回原始值 vs 返回引用值

  

构造函数在通过 `new` 调用时，默认会隐式执行 `return this;` 返回刚刚组装完毕的实例。但如果开发者在构造函数内部显式写了 `return`，结果会怎样？

  

![构造函数的返回值规则：返回原始值 vs 返回引用值](https://img.215454.xyz/file/blog/jia/1791435359959_01-constructor-return-rule.png)

  

## 1. 核心判定铁律

  

| 显式 return 的类型 | 典型示例 | 最终 `new` 出的结果 | 引擎行为解释 |

| :--- | :--- | :--- | :--- |

| **返回原始值** | `return 123;`<br>`return 'abc';`<br>`return true;`<br>`return null;`<br>`return undefined;` | **依然是创建好的 `this` 实例** | **直接无视该 return**，依然正常隐式返回 `this` |

| **返回引用值** | `return {};`<br>`return [];`<br>`return function(){};`<br>`return new Date();` | **返回你写的那个对象** | **放弃默认的 `this`**，直接将指定的引用对象交给外部 |

  

## 2. 代码验证

  

```js

// Case 1: 返回原始值（无效）

function Car1() {

this.color = 'red';

return 123; // 试图返回数字原始值

}

var c1 = new Car1();

console.log(c1.color); // 'red'（return 123 被彻底忽略！）

  

// Case 2: 返回引用值（有效，替换 this）

function Car2() {

this.color = 'red';

return function test() {

console.log(1);

};

}

var c2 = new Car2();

console.log(c2.color); // undefined（c2 变成了那个函数！）

c2(); // 1

```

  

> **设计模式延伸：工厂模式（Factory Pattern）**

> 如果不写 `new`，直接在普通函数内部手动 `var me = {}; me.color = 'red'; return me;`，这种模式就是工厂模式。`new` 运算符实际上就是把「创建空对象」和「返回 this」这两步用底层机制自动化了。

  

# 二、原始值 vs 包装类对象

  

在 JavaScript 中，数据分为**原始值**（Number, String, Boolean, undefined, null）和**引用值**（Object, Array, Function 等）。原始值本身没有属性和方法，但为什么我们能直接写 `'abc'.length` 或 `(123).toString()`？

  

![原始值 vs 包装类对象：有属性与无属性的分野](https://img.215454.xyz/file/blog/jia/1791435366624_02-wrapper-objects.png)

  

## 1. 三大包装类构造函数

  

JavaScript 针对三种常见的原始值，提供了对应的包装类构造函数：

- `new Number(value)`

- `new String(value)`

- `new Boolean(value)`

  

```js

var a = 1; // 原始值

var aa = new Number(1); // 包装类对象

  

console.log(typeof a); // 'number'

console.log(typeof aa); // 'object'

  

// 包装类对象是一个真正的堆内存对象，可以挂载属性

aa.name = '数字一';

console.log(aa.name); // '数字一'

  

// 参与算术运算时，自动调用 valueOf() 拆箱为基础值

var sum = aa + 2; // 3

console.log(typeof sum); // 'number'（运算后又变回了原始值）

```

  

> **绝对避坑警告：**

> `null` 和 `undefined` **没有任何包装类**！访问 `null.length` 或 `undefined.length` 会直接抛出致命的 `TypeError` 崩溃报错！

  

# 三、隐式包装类三步曲：为什么 `a.len = 3` 读出来是 `undefined`？

  

很多初学者容易写出类似下面的代码，看似没有任何语法错误，但结果却让人摸不着头脑：

  

![隐式包装类三步曲：为什么 a.len = 3 读出来是 undefined](https://img.215454.xyz/file/blog/jia/1791435376113_03-wrapper-lifecycle.png)

  

```js

var a = 123;

a.len = 3;

console.log(a.len); // undefined

```

  

## 底层生命周期三步拆解

  

当你试图给一个基础数据类型挂载属性或访问属性时，JS 引擎背地里执行了三步曲：

  

1. **第一步：检测到点语法操作**

引擎发现你对原始值 `a` 进行了对象专属的 `.` 访问：`a.len = 3`；

2. **第二步：隐式创建临时包装对象**

引擎偷偷在后台实例化一个临时的 `Number` 包装对象并赋值：

`new Number(a).len = 3;`

3. **第三步：没有变量持有，立即销毁！**

因为这个临时包装对象没有任何变量接收，为了避免内存泄漏，引擎在下一行代码开始前立即执行销毁：

`delete new Number(a).len;`

  

等到你执行 `console.log(a.len)` 时：

- 引擎**又一次**重新临时实例化了一个全新的 `new Number(a)` 去读 `len`；

- 这个新对象上当然空空如也，因此输出了 **`undefined`**！

  

# 四、length 属性大陷阱：数组可截断 vs 字符串只读不可截断

  

这是高频手写题中经常拿来对比的一个细节。

  

![length 属性大陷阱：数组可截断 vs 字符串只读不可截断](https://img.215454.xyz/file/blog/jia/1791435380328_04-array-vs-string-length.png)

  

## 1. 数组截断（物理有效）

  

```js

var arr = [1, 2, 3, 4, 5];

arr.length = 3;

console.log(arr); // [1, 2, 3]（后两位被直接丢弃物理销毁！）

  

arr.length = 5;

console.log(arr); // [1, 2, 3, empty x 2]（扩容出空槽）

```

  

数组是真正的复杂引用对象，它的 `length` 拥有内部 Setter，修改数字会直接触发数组内存空间的重新分配与裁剪。

  

## 2. 字符串截断（完全无效）

  

```js

var str = 'abc';

str.length = 1; // 试图截断字符串

console.log(str.length);// 依然是 3！

```

  

- `str.length = 1` 触发了隐式包装类：`new String(str).length = 1;`

- 修改只发生在那具一瞬间就被销毁的临时对象上；

- 加上原生字符串的 `length` 内部被配置为只读（`writable: false`）；

- 最终 `str` 丝毫不受影响。**JavaScript 中的原始字符串是不可变的（Immutable）**。

  

# 五、包装类高频踩坑题：`typeof` 字符串判断挂载属性

  

![包装类高频踩坑题：typeof 字符串判断挂载属性](https://img.215454.xyz/file/blog/jia/1791435383899_05-typeof-wrapper-trap.png)

  

## 1. 踩坑代码

  

```js

var name = 'languiji';

name += 10; // 'languiji10'

var type = typeof name; // 'string'（原始值！）

  

if (type.length === 6) { // 6 === 6 成立

type.text = 'string'; // 掉入包装类销毁陷阱！

}

  

console.log(type.text); // 坑点输出：undefined！

```

  

### 解析

- `typeof` 返回的值是纯原始字符串字面量 `'string'`；

- `if` 分支内执行 `type.text = 'string'` 时，产生临时包装对象挂载并瞬间销毁；

- 打印时重新包装，根本找不到 `text` 属性，输出 `undefined`。

  

## 2. 正确破局：显式 new String()

  

```js

var name = 'languiji';

name += 10;

var type = new String(typeof name); // 显式 new 包装对象！持久化在堆内存中

  

if (type.length === 6) {

type.text = 'string'; // 真实持久化挂载到该对象上

}

  

console.log(type.text); // 'string'（成功获取！）

```

  

# 六、综合算法题：字符编码与字符串真实字节数计算

  

在后端数据库存储（如 MySQL `VARCHAR` 字节限制）或短信计费系统中，通常按字节（Byte）而非字符个数计费。如何准确计算一个中英文混合字符串的真实字节数？

  

![综合算法题：字符编码与字符串真实字节数计算](https://img.215454.xyz/file/blog/jia/1791435392340_06-string-byte-length.png)

  

## 1. 编码基础原理

- **标准 ASCII 码（0 ~ 127）与扩展 ASCII（128 ~ 255）**：均占用 **1 个字节（8 位）**，如英文字母 `a` 编码是 97，逗号 `,` 是 44；

- **Unicode / 中文字符（> 255）**：涵盖汉字等象形文字，在经典前端字节计量标准中，一个汉字占 **2 个字节（16 位）**。

  

## 2. 算法实现

  

```js

function getByteLength(str) {

var totalBytes = 0;

  

for (var i = 0; i < str.length; i++) {

// charCodeAt(i) 返回第 i 个字符的 Unicode 整数编码

var code = str.charCodeAt(i);

  

if (code <= 255) {

totalBytes += 1; // 属于 ASCII 范围，占 1 字节

} else {

totalBytes += 2; // 大于 255（如中文汉字），占 2 字节

}

}

  

return totalBytes;

}

  

console.log(getByteLength('abc')); // 3

console.log(getByteLength('你好')); // 4

console.log(getByteLength('hello世界')); // 5 + 4 = 9

```

  

> **极客简化写法：**

> ```js

> function getByteLength(str) {

> var len = str.length;

> for (var i = 0; i < str.length; i++) {

> if (str.charCodeAt(i) > 255) len++;

> }

> return len;

> }

> ```

> 先假定每个字符都是 1 字节，每遇到一个汉字额外 `len++` 加补 1 个字节，逻辑更为精巧。

  

# 本课小结

  

- **构造函数返回值规则**：

- 显式 `return` **原始值** → 无效，被直接忽略，依然返回 `this`；

- 显式 `return` **引用值** → 生效，丢弃 `this`，改以返回该引用对象；

- **包装类的本质**：为了让原始值能够临时调用原型方法（如 `toString`、`toFixed`），引擎在幕后通过 `new Number / String / Boolean` 进行动态包装；

- **包装类生命周期三步曲**：访问属性时临时创建 → 挂载属性 → 语句结束瞬间立即销毁；

- **数组可物理截断，字符串不可变**：`arr.length = 3` 可以截断数组；`str.length = 1` 只是改了临时的包装对象，字符串本身毫发无损；

- **编码与字节算法**：`str.charCodeAt(i)` 区分 ASCII（`<= 255`，1 字节）与双字节字符（`> 255`，2 字节），是字符计量工程的经典算法。
