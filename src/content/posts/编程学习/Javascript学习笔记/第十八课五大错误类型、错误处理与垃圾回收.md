# JS 第十八课：五大错误类型、错误处理与垃圾回收

  

> 本课对应练习文件：`index.html`（SyntaxError / ReferenceError / RangeError / TypeError / URIError 五大错误类型现场、Error 对象与手动抛错、try / catch / finally / throw 错误处理四件套、严格模式 'use strict' 约束、标记清除与引用计数垃圾回收机制、闭包与内存回收）。

  

# 一、五大错误类型总览：报错信息速查表

  

![五大错误类型总览：报错信息速查表](https://img.215454.xyz/file/blog/jia/1792060380750_01-five-errors-overview.png)

  

| 错误类型 | 什么时候出现 | 典型现场 |

| :--- | :--- | :--- |

| **SyntaxError** 语法错误 | 解析阶段就被拦下：变量名不规范、关键字乱赋值、标点写错 | `var 1 = 1;` → Unexpected number |

| **ReferenceError** 引用错误 | 名字找不到（没声明就使用）；给无法赋值的目标赋值 | `console.log(a);` → a is not defined |

| **RangeError** 范围错误 | 数值 / 长度越出合法范围 | `arr.length = -1` → Invalid array length |

| **TypeError** 类型错误 | 类型不对路：调用不存在的方法、用原始值 new | `123();` → is not a function |

| **URIError** URI 错误 | 编解码时参数不是合法 URI | `decodeURI('%fdsd%')` → URI malformed |

| EvalError（罕见） | 与 eval 有关的历史遗留类型，现代引擎几乎不再抛出 | 认识名字就行 |

  

> **速记：** 语法错"没跑就拦"、引用错"名字丢了"、范围错"数值越界"、类型错"对不上号"、URI 错"编解码参数有毛病"。

>

> **冷知识：** `JSON.parse('')` 抛的是 **SyntaxError**（Unexpected end of JSON input）—— **错误类型由"出错原因"决定，不是由代码出现在哪里决定的**。

  

# 二、最常撞见的两位：SyntaxError 与 ReferenceError

  

![最常撞见的两位：SyntaxError 与 ReferenceError](https://img.215454.xyz/file/blog/jia/1792060388448_02-syntax-reference.png)

  

## 1. SyntaxError：代码"没资格跑"

  

```js

var 1 = 1; // Uncaught SyntaxError: Unexpected number 意外的数字

var 1ab = 1; // Invalid or unexpected token 无效的意外标记

new = 5; // 关键字不可赋值 → Unexpected token '='

var a = 5: // 基本语法错 → Unexpected token ':'

```

  

解析（预编译）阶段引擎就发现语法畸形，**整段脚本一行都不会执行** —— 所以一看到 SyntaxError，先检查拼写、标点和变量名，别找逻辑问题。

  

## 2. ReferenceError：名字查无此人 / 赋值无门

  

```js

console.log(a); // ReferenceError: a is not defined

test(); // 调没声明的函数同样中招

  

console.log(a) = 1;

// ReferenceError: Invalid left-hand side in assignment

// 赋值号左侧没有"落脚点"——函数调用的结果不可被赋值

```

  

两个场景：

1. **名字找不到**：变量 / 函数没声明就使用；

2. **赋值无门**：赋值号左侧必须是"能被赋值的引用"（变量、对象属性），往函数调用结果上赋值直接报 `Invalid left-hand side`。

  

> **小提醒：** `var a = 1 = 2;` 这种字面量赋值目标在现在的引擎里是**解析期**就报 SyntaxError，而 `console.log(a) = 1` 是**运行期** ReferenceError —— 发现时机不同，错误类型就不同。

  

> **对比记忆：** SyntaxError = "话都说不利索"（解析阶段拦下，一行都不跑）；ReferenceError = "喊的名字查无此人"（跑着跑着才发现）。

  

# 三、数值与类型的岔路：RangeError 与 TypeError

  

![数值与类型的岔路：RangeError 与 TypeError](https://img.215454.xyz/file/blog/jia/1792060397526_03-range-type.png)

  

## 1. RangeError：管"量"

  

```js

var arr = [1,2,3];

arr.length = -1;

// RangeError: Failed to set the 'length' property on 'Array':

// Invalid array length 无效的数组长度

  

var num = new Number(66.66);

console.log(num.toFixed(1)); // "66.7" 正常

console.log(num.toFixed(-1));

// RangeError: toFixed() digits argument must be between 0 and 100

```

  

数值、长度超出引擎允许的合法范围时登场：数组长度不能为负；`toFixed` 的小数位数必须在 0~100。都是"**量**"出了问题。

  

## 2. TypeError：管"型"

  

```js

123(); // TypeError: 123 is not a function

var obj = {};

obj.say(); // TypeError: obj.say is not a function

console.log(obj.say); // undefined —— 只读不报错！

  

new 'string'; // TypeError: "string" is not a constructor

new 123; // TypeError: 123 is not a constructor

```

  

两大场景：

1. **调用不存在的方法** —— 注意：**读取** `obj.say` 只是 `undefined` 不报错，**调用**它才炸；

2. **实例化原始值** —— `new` 后面必须跟构造函数。

  

> **分辨口诀：** RangeError 管"数值超界"，TypeError 管"类型不对"。错误处理的第一步永远是"读懂报错"：**名字**指明大方向、**message** 交代细节、**行号**负责精确定位。

  

# 四、URI 家族与编解码：中文是怎么"上车"的

  

![URI 家族与编解码：中文是怎么"上车"的](https://img.215454.xyz/file/blog/jia/1792060401253_04-uri-encode.png)

  

## 1. 概念辨析：URI、URL、URN

  

```js

// URI = UNIFORM RESOURCE IDENTIFIER 统一资源标识符

// URL = UNIFORM RESOURCE LOCATOR 统一资源定位符

// URN = UNIFORM RESOURCE NAME 统一资源名称

  

// URI 是总称：URL 和 URN 都算 URI

// href="tel:139000000" ← 算 URI

// href="mailto:xxx@qq.com" ← 算 URI

```

  

> **一句话记忆：** URI 是"**身份证号**"级别的总称号（标识符）；URL 是"**家庭住址**"（能定位到资源）；URN 是"**姓名**"（只给资源起名）。

  

## 2. 编解码往返与 URIError

  

```js

var myUrl = 'http://www.baidu.com?name=爱宵夜';

var newUrl = encodeURI(myUrl);

// http://www.baidu.com?name=%E7%88%B1%E5%AE%B5%E5%A4%9C

  

var oldUrl = decodeURI(newUrl);

// 变回：http://www.baidu.com?name=爱宵夜

  

decodeURI('%fdsd%');

// Uncaught URIError: URI malformed —— 参数不是合法 URI

```

  

- `encodeURI` 把中文字符转成 **%XX 百分号编码**（"爱" → `%E7%88%B1`，UTF-8 占 3 字节 → 三组 %XX）；

- `decodeURI` 再转回来；

- **为什么中文要转码？** URL 只能安全携带 ASCII 字符，中文必须转码才能安全传输。

  

# 五、错误处理四件套：try / catch / finally / throw

  

![错误处理四件套：try / catch / finally / throw](https://img.215454.xyz/file/blog/jia/1792060406853_05-try-catch-finally.png)

  

## 1. 系统抛错：一错全停

  

```js

console.log('正常执行1');

console.log(a); // ReferenceError: a is not defined

console.log('正常执行2'); // 永远不会执行 —— 第一处错误立即中断

```

  

## 2. 手动创建 Error 对象

  

```js

var error = new Error('代码错误');

// var error = new ReferenceError('代码错误');

// var error = new SyntaxError('代码错误');

// var error = new TypeError('代码错误');

console.log(error); // name: "Error" message: "代码错误"

```

  

`new Error` / `new TypeError` / `new ReferenceError`… 都能手动造错误对象，**name + message** 是两大核心字段。

  

## 3. try / catch / finally 全流程（实测推演）

  

```js

try{

console.log('正常执行1');

console.log(a); // ← 执行到这儿报错

console.log('正常执行2'); // 不再执行

}catch(e){

console.log(e.name + ': ' + e.message);

// 输出：ReferenceError: a is not defined

}finally{

console.log('正常执行3');

}

console.log('正常执行4');

```

  

**执行顺序（实测）：** 正常执行1 → catch（ReferenceError: a is not defined）→ finally 正常执行3 → 正常执行4。

  

| 关键字 | 职责 |

| :--- | :--- |

| `try` | 圈出"可能有风险"的代码；出错点之后的代码不再执行 |

| `catch(e)` | 接住 try 里的错误；try 一切正常就不走它 |

| `finally` | **天塌下来也执行**（对错都走） |

  

## 4. throw：抛自定义错误

  

```js

var jsonStr = '';

try{

if (jsonStr === ''){

throw 'JSON字符串为空'; // 自定义错误：throw 什么都能抛

}

var json = JSON.parse(jsonStr);

}catch(e){

console.log(e); // 接住 'JSON字符串为空'

// 实际工程里通常会记录日志 + 提示用户

}

```

  

> **冷知识：** `JSON.parse('')` 抛的是 **SyntaxError**（Unexpected end of JSON input）—— 错误类型由"出错原因"决定。

  

# 六、严格模式 'use strict'：把宽松的口子逐个收紧

  

![严格模式 'use strict'：把宽松的口子逐个收紧](https://img.215454.xyz/file/blog/jia/1792060416885_06-strict-mode.png)

  

```js

'use strict'; // 写在脚本/函数的第一行才生效

  

// 禁令 1：with 语句被禁用

// SyntaxError: Strict mode code may not include a with statement

  

// 禁令 2：函数参数名不能重复

// SyntaxError: Duplicate parameter name not allowed in this context

```

  

## 严格模式 vs 非严格模式：宽容度对照

  

| 场景 | 非严格模式 | 严格模式 |

| :--- | :--- | :--- |

| 重复 `var` 声明 | 不报错，后者生效 | 允许（var 声明仍合法） |

| 同名函数声明 | 后者覆盖前者（预编译） | 同左 |

| 对象属性名重复 | 不报错，后者覆盖 | 同左 |

| **函数参数名重复** | 不报错 | **SyntaxError** |

| **with 语句** | 可用（改变作用域链） | **SyntaxError** |

| **隐式全局变量**（未声明就赋值） | 静默变成全局 | **ReferenceError** |

| **eval 作用域** | eval 里的 var 泄漏到外层 | eval 有自己的作用域，外部拿不到 |

  

```js

// 严格模式：eval 有自己的作用域

eval('var a = 1; console.log(a)'); // 内部打印 1

console.log(a); // ReferenceError: a is not defined

  

// 非严格模式：eval 里的 var 会"漏"到外层

eval('var yy = 1'); // yy 泄漏到外部作用域

```

  

> 顺带认识 `eval`：`eval('1') → 1`，能把字符串当代码执行 —— 能力强、风险大，现代开发基本弃用。

  

# 七、垃圾回收机制：谁会被"扫地出门"？

  

![垃圾回收机制：谁会被"扫地出门"？](https://img.215454.xyz/file/blog/jia/1792060424063_07-gc-recycling.png)

  

## 1. 三部曲与标记清除（Mark and Sweep）

  

```js

// 垃圾回收三部曲（引擎自动完成）：

// 1. 找出不再使用的变量

// 2. 释放其占用的内存

// 3. 固定时间间隔运行

  

// 标记清除：

function test(){

var a = 0; // 进入环境 → 打上标记

}

test(); // 离开环境 → 等待回收

```

  

变量进入环境时打"标记"；离开环境（函数执行完、引用消失）就进回收名单。**全局变量永远在环境里** —— 生命周期跟随页面，这就是"少用全局变量"的原因之一。

  

## 2. 引用计数与"循环引用死结"

  

```js

// 引用计数：有几个引用指着它，为 0 就回收

  

// 死结：循环引用

function test(){

var a = new Object(); // a 计数 1

var b = new Object(); // b 计数 1

a.prop = b; // b 计数 2

b.prop = a; // a 计数 2

a = null; b = null; // 互指，计数永不归零！

}

```

  

- 纯引用计数会被"互指的孤岛"困死；

- 现代引擎以**标记清除**为主力 —— 从根对象出发扫"够得着谁"，扫不到的统统端走，循环引用照样收拾。

  

## 3. 闭包 = 有意的"不回收"

  

```js

function test1(){

var a = 1;

return function(){

a++;

console.log(a);

};

}

var test3 = test1();

test3(); // 2

test3(); // 3

test3(); // 4 —— 引用链不断，a 常驻内存

test3 = null; // 解除引用，下一次回收才轮到它

```

  

闭包让局部变量"常驻内存"（这就是第十七课计数器的原理）—— **既是封装利器，也是内存泄漏的常见源头，用完记得松手**。

  

# 本课小结

  

- **五大错误类型**：SyntaxError（解析期拦下）、ReferenceError（名字丢了）、RangeError（数值越界）、TypeError（类型不对）、URIError（编解码参数有毛病）；错误类型由"出错原因"决定；

- **读懂报错三件套**：名字指明方向、message 交代细节、行号精确定位；

- **URI 家族**：URI 是总称，URL 能定位、URN 只命名；`encodeURI` / `decodeURI` 互逆往返，中文按 UTF-8 编成 %XX；

- **错误处理**：系统抛错"一错全停"；`try` 圈风险、`catch` 接错误、`finally` 必执行、`throw` 自定错误；Error 对象的 `name` + `message` 是核心字段；

- **严格模式**：`'use strict'` 收紧宽松口子（with、重复参数名、隐式全局、eval 作用域）；

- **垃圾回收**：标记清除为主、引用计数为理解模型；循环引用是引用计数的死结；闭包是"有意的内存常驻"。
