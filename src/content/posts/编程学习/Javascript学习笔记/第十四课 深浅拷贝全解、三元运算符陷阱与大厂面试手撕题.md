# 一、三目运算符精通：嵌套求值与字符串 ASCII 比大小

  

三目（三元）运算符是替代简单 `if-else` 的利器，但在多层嵌套或涉及字符串比较时隐藏着极深的反直觉陷阱。

  

![三目运算符精通：嵌套求值与字符串 ASCII 比大小](https://img.215454.xyz/file/blog/jia/1791815450322_01-ternary-operator-traps.png)

  

## 1. 嵌套三目运算符的求值顺序

  

```js

var a = 5;

var str = a > 0 ? (

a > 3 ? '大于3'

: '小于等于3'

) : '小于等于0';

  

console.log(str); // '大于3'

```

  

- **右结合性**：引擎从最外层条件开始断定，真则深入内层真分支，假则走向冒号右侧；

- **书写规范**：嵌套时**必须加括号分层**，否则代码的可读性与后期维护性将彻底雪崩。

  

## 2. 高频陷阱：`'89' > '9'` 为什么是 `false`？！

  

```js

var res = 89 > 9 ? (

'89' > '9' ? '通过了'

: '内层未通过'

) : '外层未通过';

  

console.log(res); // 坑点输出：'内层未通过' ！！

```

  

### 深度解密

1. 外层数值比对：数字 `89 > 9` 为真，顺利步入内层；

2. 内层比对：`'89' > '9'` 左右两侧都是字符串！

3. **字符串比大小规则**：绝不会转成数字，而是**按第一位字符的 ASCII 编码逐位对比**！

4. 字符 `'8'` 的 ASCII 码是 56，字符 `'9'` 的 ASCII 码是 57。因为 `56 < 57`，所以引擎断定 `'89' < '9'`！

  

> **实战防坑守则：**

> 任何来自 `window.prompt`、表单输入、URL 参数的数据，**默认全都是字符串类型**！在用比较运算符前，必须显式调用 `parseInt()` 或 `Number()` 转为纯数字，否则必遭 ASCII 比对暗算！

  

# 二、克隆的本质：直接赋值 vs 浅拷贝（Shallow Clone）

  

在 JavaScript 中，引用类型变量存储的只是堆内存的“指针地址”，这也催生了不同层次的复制拷贝概念。

  

![克隆的本质：直接赋值 vs 浅拷贝](https://img.215454.xyz/file/blog/jia/1791815461687_02-shallow-clone-concept.png)

  

## 1. 直接赋值（传递指针，非克隆）

  

```js

var person1 = { name: '张三', age: 18 };

var person2 = person1; // 只是复制了栈内存里的指针引用！

  

person2.name = '李四';

console.log(person1.name); // '李四' ！！原对象同步被改！

```

  

两者共用同一个物理堆地址，修改任何一方的属性，另一方完全联动改变。

  

## 2. 浅拷贝（仅遍历克隆第一层）

  

```js

function clone(origin, target) {

var tar = target || {};

for (var key in origin) {

if (origin.hasOwnProperty(key)) {

tar[key] = origin[key]; // 仅做一层赋值！

}

}

return tar;

}

```

  

### 浅拷贝的致命软肋

如果原始对象包含嵌套结构（如 `children: { first: {...} }` 或 `car: ['Benz']`），浅拷贝仅仅把内层对象的地址指针拷贝了过去：

```js

var person2 = clone(person1);

person2.car.push('BYD');

console.log(person1.car); // ['Benz', 'BYD'] ！！原对象的子属性依然被污染！

```

  

# 三、深拷贝四部曲算法（Deep Clone）：手写递归核心

  

为了彻底斩断深层嵌套引用的纽带，必须手写递归遍历实现**深拷贝**。

  

![深拷贝四部曲算法：手写递归核心](https://img.215454.xyz/file/blog/jia/1791815465720_03-deep-clone-algorithm.png)

  

## 标准递归深拷贝实现

  

```js

function deepClone(origin, target) {

var tar = target || {};

var toStr = Object.prototype.toString;

var arrType = '[object Array]';

  

for (var key in origin) {

if (origin.hasOwnProperty(key)) {

var item = origin[key];

  

// 1. 判定是否为非 null 的引用对象

if (typeof item === 'object' && item !== null) {

// 2. 区分是数组还是普通对象，开辟全新内存

if (toStr.call(item) === arrType) {

tar[key] = [];

} else {

tar[key] = {};

}

// 3. 递归深入下一层叶子节点克隆

deepClone(item, tar[key]);

} else {

// 4. 基础类型原始值，直接赋值

tar[key] = item;

}

}

}

  

return tar;

}

```

  

## 避坑要点提示

- 必须用 `origin.hasOwnProperty(key)` 过滤原型继承的污染属性；

- `typeof null === 'object'`，判定时必须显式加入 `item !== null` 守卫；

- 课件原始手写代码中曾有 `toStr.call(origin[key] === arrType)` 的括弧笔误，正确必须是 **`toStr.call(item) === arrType`**！

  

# 四、JSON 序列化深拷贝：一行代码的奇迹与四大致命短板

  

除了手写递归，工程中最常用的快捷手段是 `JSON.parse(JSON.stringify(obj))`。

  

![JSON 序列化深拷贝：一行代码的奇迹与四大致命短板](https://img.215454.xyz/file/blog/jia/1791815475154_04-json-clone-limitations.png)

  

```js

var person1 = {

name: '张三',

car: ['Benz', 'Mazda'],

children: { first: { name: '张小一' } }

};

  

var person2 = JSON.parse(JSON.stringify(person1));

person2.car.push('BYD');

console.log(person1.car); // ['Benz', 'Mazda']（完美独立！）

```

  

## JSON 深拷贝的四大致命短板

  

| 缺陷场景 | 具体表现 | 引擎原因 |

| :--- | :--- | :--- |

| **函数与特殊值丢失** | `function`、`undefined`、`Symbol` 属性直接**被静默抹除丢弃** | JSON 标准规范中不支持函数与未定义类型 |

| **特殊引用对象变异** | `RegExp` 沦为空对象 `{}`；`Date` 异化为纯时间字符串 | 无法还原原生构造对象 |

| **原型链丢失** | 构造函数创建的实例被还原为普通 `Object`，丢失原型上的方法 | 仅序列化自身可枚举数据属性 |

| **循环引用崩溃** | 对象自身存在循环引用时，直接抛出 `Converting circular structure to JSON` 异常崩溃 | 无法处理图状指针拓扑结构 |

  

> **选型建议：** 纯前后端交互的业务 DTO 数据，用 `JSON.parse(JSON.stringify())` 性能最极致；涉及通用库、复杂对象树，务必采用手写递归 `deepClone`。

  

# 五、经典面试手撕题一：预编译函数覆盖（1, 4, 4 惨案）

  

![经典面试手撕题：预编译提升与函数覆盖](https://img.215454.xyz/file/blog/jia/1791815484698_05-function-override-hoisting.png)

  

```js

var x = 1,

y = z = 0;

  

function add(n) {

return n = n + 1;

}

  

y = add(x);

  

function add(n) {

return n = n + 3;

}

  

z = add(x);

  

console.log(x, y, z); // 惊人输出：1, 4, 4 ！！

```

  

## 深度推演解析

1. **预编译阶段（GO 建立）**：

- 扫描到第一个 `function add`，紧接着又扫描到第二个同名 `function add`；

- **函数声明后者必胜**：第二个加 3 的版本彻底覆盖了第一个版本！加 1 的版本从一开始就不复存在！

2. **执行阶段**：

- 执行 `y = add(x)` 时，调用的正是加 3 版本：`1 + 3 = 4`，故 `y = 4`；

- 执行 `z = add(x)` 时，依然是加 3 版本：`1 + 3 = 4`，故 `z = 4`；

3. **为什么 x 没变？**

- 函数内部 `return n = n + 3` 仅仅改写了局部形参 `n`，外部原始值变量 `x` 从未被重新赋值，依然为 `1`。

  

# 六、神级面试压轴题：Foo().getName() 七问全通关

  

这是一道集变量提升、构造函数、原型链、成员访问优先级于一体的巅峰压轴题。

  

![神级面试压轴题：Foo().getName() 七问全通关](https://img.215454.xyz/file/blog/jia/1791815499412_06-foo-getname-seven-traps.png)

  

```js

function Foo() {

getName = function () { console.log(1); };

return this;

}

Foo.getName = function () { console.log(2); };

Foo.prototype.getName = function () { console.log(3); };

var getName = function () { console.log(4); };

function getName() { console.log(5); }

  

// 七问连环拆解：

Foo.getName(); // ① 输出：2

getName(); // ② 输出：4

Foo().getName(); // ③ 输出：1

getName(); // ④ 输出：1

new Foo.getName(); // ⑤ 输出：2

new Foo().getName(); // ⑥ 输出：3

new new Foo().getName(); // ⑦ 输出：3

```

  

## 逐问深度剖析

  

1. **`Foo.getName()` → 2**：直接访问函数对象自身的静态方法，输出 2；

2. **`getName()` → 4**：预编译期函数声明 5 被后面的 `var getName = function(){4}` 表达式赋值覆盖，输出 4；

3. **`Foo().getName()` → 1**：普通调用 `Foo()`，内部把全局 `getName` 改为 1，并返回 `this`（`window`），等价于 `window.getName()`，输出 1；

4. **`getName()` → 1**：因为上一问全局 `getName` 已被修改为 1，此时再次独立调用依然输出 1；

5. **`new Foo.getName()` → 2**：成员访问 `.`（优先级 19）高于无参数列表 `new`（优先级 18），等价于 `new (Foo.getName)()`，把静态方法当构造函数实例化，输出 2；

6. **`new Foo().getName()` → 3**：带参数列表的 `new Foo()`（优先级 19）与成员访问 `.` 平级，从左往右结合，等价于 `(new Foo()).getName()`。实例自身没有，顺着原型链找到 `Foo.prototype.getName`，输出 3；

7. **`new new Foo().getName()` → 3**：等价于 `new ((new Foo()).getName)()`，以第 6 问找出的原型函数作为构造函数再次实例化，输出 3！

  

# 本课小结

  

- **三目运算符比大小**：字符串比较按 ASCII 逐位对比，涉及用户输入必须先转数字；

- **浅拷贝 vs 深拷贝**：浅拷贝只拷贝一层，深层引用依然互相牵连；深拷贝必须递归断开所有层级的对象引用；

- **手写深拷贝四部曲**：`for...in` 遍历 → `hasOwnProperty` 过滤原型 → `typeof === 'object' && !== null` → `Object.prototype.toString` 区分数组/对象递归开辟；

- **JSON 深拷贝边界**：纯数据最快，但会丢失函数、undefined、RegExp/Date 变异且遇循环引用抛错；

- **同名函数声明**：预编译期**后者必胜**，全量覆盖前者；

- **运算符优先级**：带参 `new Foo()`（19） = 成员访问 `.`（19） > 无参 `new Foo`（18）。
